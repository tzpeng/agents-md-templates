# Bugfix
- 铁律：先定位根因再修，不做“症状修复”；没完成根因调查就不提修复方案。
- 根因：读全错误信息（dmesg、/mnt 下日志、app 日志，留意行号/错误码）；在板上稳定复现（记录确切步骤）；查最近改动（git log/diff、config 变更）。
- 对照：找同仓库里能跑的相似实现（chassisd 变体或其它 app），逐行对比差异，别假定“这个不可能影响”。
- 假设：一次只提一个明确假设（“X 是根因，因为 Y”），做最小改动验证，一次只动一个变量；不成立就换假设，不叠加修复。
- 落地：先写最小失败用例（能复现），再单一修复，上板跑 board.sh smoke 全过且原现象消失；连续 3 次修不好就停下来质疑架构、先跟人讨论，不再打补丁。
- 跨层（RPC/协议帧/驱动/应用）：在每层边界加日志/抓包，先定位哪一层丢数据，再深入那一层。
